# 状態通知とEngine取得のAlloc削減

2026-10-18。[ベースライン](2026-10-18-baseline.md)と同じスクリプト・測定回数・校正方法・Unity／CPUで再測定した。測定スクリプトの変更はNotesの説明文のみで、操作と計測条件は変更していない。

## 変更

- 未購読時にも生成されていた通知クロージャを除去した。
- 通知ごとのGetInvocationListを廃止し、購読・解除時に不変の呼び出し一覧を作る。遷移時点の一覧を保持するため、キュー投入後の購読変更が過去の通知へ遡及しない。
- Post用コールバックを静的に保持し、通知オブジェクトを再利用する。プールに保持する待機オブジェクトは最大256個。返却時はHandleと購読者一覧を消去する。
- OrbitContext.Getは検証用HashSetを再利用し、配列をインデックスで走査する。既存Engineでも毎回Key検証を維持し、定義変更の検出を省略するキャッシュは導入していない。
- 公開API、通知順序、メインスレッド配信、購読者ごとの例外分離、Ended時の結果確定は維持した。

## 結果

Allocは操作1回あたり、時間は7試行の中央値。Pause→Resumeは2遷移を合わせた値。

| 条件 | Alloc 変更前→変更後 | 時間 µs 変更前→変更後 |
|---|---:|---:|
| 保持したHandleでPause→Resume、購読者なし | 80 B → **0 B** | 0.569 → 0.272 |
| 同操作、購読者1人・配信込み | 416 B → **0 B** | 1.527 → 0.943 |
| 同操作、購読者8人・配信込み | 528 B → **0 B** | 1.902 → 1.122 |
| 既存Engineの取得、定義1件 | 220 B → **0 B** | 1.026 → 0.399 |
| 登録済みKeyで再生→停止、購読なし | 2,984 B → 2,912 B | 20.190 → 20.781 |
| 再生→Pause→Resume→停止、購読なし | 3,064 B → 2,912 B | 20.767 → 21.413 |
| 同操作、購読者1人・キュー投入まで | 3,448 B → 2,992 B | 23.228 → 25.932 |
| Direct参照で再生→停止、購読なし | 3,428 B → 3,356 B | 20.439 → 20.680 |
| 事前ロード済み参照で再生→停止、購読なし | 3,496 B → 3,424 B | 26.822 → 24.507 |

通知配信込みの測定は確保済みの専用SynchronizationContextでキューを処理するため、Unity固有のキュー内部コストは含まない。実際のUnityキューを使う再生サイクルの測定では、発音後に購読し、Paused・Playing・Endedの3通知をキューへ投入する。

保持済みHandleでの継続的な通知と、既存Engine取得のウォーム経路では0Bを確認した。**すべての通知・再生でAllocゼロになったわけではない。** 初回の通知、購読・解除、プールを超える集中通知では確保が発生する。キューが詰まった場合に増え続けるプールは設けず、256個までの再利用に限定している。再生1回のAllocにはHandle、Task、CTSなどが残る。

購読者1人の配信込みのCPU時間は今回約38%減少したが、再生サイクル全体のCPU時間は一律には改善していない。特に購読者1人のキュー投入条件は中央値が増加しているため、全体のCPU高速化とは結論しない。今回の主成果は定常通知とEngine取得のAlloc削減である。Editor／Monoの値であり、IL2CPP Playerへの一般化はしない。

## 計測の確認

- 校正用4096バイト配列はヘッダー込み4128B、空操作は0Bだった。
- Allocは各条件128回×3試行。上記ゼロAlloc条件は3試行とも0B／0イベントだった。
- 通知順序・失敗結果・購読変更・128個のHandleへの集中通知・例外分離・コールバックからのStopAll、およびContextの定義検証等、25件のテストが成功した。Edit Mode実行のためRuntime専用の既存1件は対象外。
- 最初の再測定ではCPU時間が全般的に増加していた。Deep Profiling無効状態でクリーン再コンパイル後に取り直した結果を採用した。原因をProfiler計装に断定はせず、最初の記録も保存している。Allocは両回で同じ値だった。
- 元のProfiler設定（Deep Profiling有効）とEdit Modeに戻した。ユーザーのシーンは保存していない。
